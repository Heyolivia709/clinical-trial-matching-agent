# Admit orchestration comparison and live mode after the MVP

[ADR 0003](0003-keep-phase-1-read-only-and-cognition-focused.md) excluded LangGraph, multi-agent orchestration, MCP, and deployment work to protect the benchmark-first cognition work. That exclusion was scoped to the MVP and is now discharged rather than reversed: the post-MVP sequence admits a component only when it answers a question the specification already owes an answer to. Specification section 16 calls plain typed Python the orchestration baseline without ever comparing it to one; section 15.3 declares a live mode that section 19 puts fourth in the cut order and will therefore most likely ship unbuilt; and the verifier's ability to bound adversarial trial text is a structural claim the MVP's injected-fault fixtures never test, because those attack the citation rather than the prompt. Adding technologies to demonstrate familiarity was rejected because it would dilute the one claim the MVP's evaluation supports, and admitting them as replacements rather than as measured variants behind existing interfaces was rejected because the comparison is the result worth publishing.

Two consequences are accepted. Orchestration comparisons run on the development partition and are labelled as such, because the held-out partition is consumed by the MVP comparison and pre-registration section 5.3 puts the resolvable difference at 15–25 points — wider than any difference two implementations of the same logic should produce. And the deployed live mode is an operational envelope for a single run, not a demonstration surface: [ADR 0007](0007-deliver-a-static-trace-report.md) stands, and the two static artifacts remain what a reviewer reads.
