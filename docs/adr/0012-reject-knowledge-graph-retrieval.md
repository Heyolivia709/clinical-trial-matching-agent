# Reject knowledge-graph retrieval

A property graph over trials, criteria, and normalized concepts would express real structure in this domain, and multi-hop expansion such as resolving a drug class to its members is a natural traversal. It is rejected because this project has nothing left for it to attach to. Criterion Expressions are hand-authored under [ADR 0004](0004-hand-author-criterion-expressions.md), so there is no parsing step a graph could inform; per-facet retrieval decomposition and cross-encoder reranking are both out of scope under specification section 18, so the retrieval pipeline has no stage that consumes structure beyond two channels and a fusion; and the terminology surface is a small reviewed mapping set, so a graph would restate it in another store. The remaining option — permitting the graph to infer relationships that no reviewed mapping asserts — is prohibited outright, since only reviewed mappings may establish `met` or `not_met`.

Model-proposed query expansion already exists for the one purpose a graph would legitimately serve, and specification section 9 bounds it correctly: it may improve retrieval and can never establish a Criterion State. Should a later phase need traversal that reviewed mappings cannot express, the case has to be made against the retrieval benchmark rather than assumed from the shape of the domain.
